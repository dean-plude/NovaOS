NovaOS 0.2.2 "Pulsar" is planned as the release where Windows Store apps
start for real. Starlight (0.2.1) built the XAML framework, WinUI 2 and app
packages, and Windows Calculator's Store package installs unchanged; Pulsar
makes the system XAML a Windows component apps can activate, so Calculator
opens and computes, and carries the Intel GPU's render path one step on,
towards games on the GPU.

## Must

1. **A system `Windows.UI.Xaml.dll`** (32.6, size L). Today the XAML
   framework is a static library linked into the test programs, which
   register its classes themselves. Build it as a system DLL with
   `DllGetActivationFactory`, and list every `Windows.UI.Xaml` class under
   `ActivatableClassId` in the registry, as Windows does. Done when a test
   program gets `Windows.UI.Xaml.Application` from `RoGetActivationFactory`
   with no registration of its own and runs a page, and the XAML tests use
   the DLL.
   *Status:* the DLL and the registry keys are in, with `xamldlltest`.
   The older XAML self-tests still link the framework into themselves,
   as they reach into its internals; the DLL sees that and leaves their
   classes to them.  A UWP app's own `OnLaunched` (Windows' arguments)
   comes with item 3.
2. **The Windows Runtime classes Calculator asks for next** (32.6, size M):
   `Windows.System.MemoryManager` and
   `Windows.System.Threading.ThreadPool` activation factories, and any
   further class its start-up asks for. Done when Calculator gets past
   `RoGetActivationFactory` without `0xc0000602`.
   *Status:* `MemoryManager`, `ThreadPool` and `ThreadPoolTimer` are in
   `twinapi.appcore.dll` with their registry keys, with `wrtpooltest`.
   Calculator no longer asks for a class NovaOS lacks: it reaches
   `CoreApplication.Run` and then stops (`0x80004001`) on XAML core
   functions not built yet (`XamlOneCoreTransforms`,
   `XcpAllocation::EnableMemoryTracking` ...), which is item 3.
3. **Windows Calculator starts** (32.6, size L, open-ended). The Store
   bundle runs its own `Microsoft.UI.Xaml.dll` 2.8 from the framework
   package on top of the system XAML, with its .NET Native runtime. Done
   when `appx start Microsoft.WindowsCalculator_8wekyb3d8bbwe!App` opens
   Calculator's window and it computes `2 + 2`, in a CI check; this ticks
   step 32.6 and completes Phase 32.
   *Status:* first slice in: Calculator's `App` is made, its window opens
   and its `OnLaunched` runs (Application override faces, faces that are
   part of their objects, the launch's User and splash screen,
   `ResourceContext` qualifiers, `User`, `NamedPolicy`,
   `ApplicationView`, `ApplicationData.LocalSettings`, an FLS fix for
   .NET Native's thread exit, all of WinUI 2's classes registered).  It
   now stops on `Windows.Globalization.ApplicationLanguages`: the
   `Windows.Globalization` classes are the next slice, then its pages'
   remaining gaps and the CI check.
   Second slice in: a new `Windows.Globalization.dll` (languages,
   regions, preferences, calendar, number, currency and date
   formatters); Calculator gets past them and next stops on
   `CoreDragDropManager`, `AsyncCausalityTracer` and an unhandled
   `E_FAIL` in `Windows.UI.Xaml.dll`.
4. **GPU sharing by NT handle** (25.3, step 3 part 6 of the
   [Intel GPU design](../design/intel-gpu.md), size M):
   `D3DKMTShareObjects`, opening allocations and sync objects from an NT
   handle in another process, and the 32-bit structure translation, as
   VKD3D-Proton uses them. Done when `kmttest wddm` shares an allocation
   and a fence between two processes on QEMU, x64 and x86.

## Nice

5. **XAML `TextBox`** (size M to L): a windowless RichEdit
   (`ITextServices` and `ITextHost`) under XAML's text box, the largest
   gap Starlight's notes list. Done when a XAML page's `TextBox` takes
   typing and selection.
6. **Retire the Venus present hang** (size S to M): find the root cause
   of the `d3dtest present x86` hang on Venus, the last open flake in the
   graphics suite.
7. **Bluetooth in Settings** (28.2, size M): a Settings > Bluetooth page,
   and reconnects that the device starts, both checkable in the devices
   suite's `bluetooth` boot.
8. **Update signing key** (23.5, size S, needs Dean): Dean makes the
   release key pair; its public half goes into `kernel/fs/update_key.h`,
   and a signed test update is accepted and an unsigned one refused.

## Not in this release

Checks on the T14 itself (Wi-Fi, Bluetooth, camera, battery, the Intel
driver, 23.2, 24.5, 25.4, 25.5) and store sign-ins (24.1, 24.2, 24.6)
need Dean's hardware or accounts; they tick whenever they are done and
do not hold the release. App compatibility rounds stay paused (OS work
only).
