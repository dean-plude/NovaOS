> **Planned, not released.** This is the scope NovaOS 0.2.3 "Nebula" is
> working towards, agreed on 2026-10-26, after 0.2.2 "Pulsar" was planned
> ([0.2.2.md](0.2.2.md)). The release-prep pull
> request rewrites this file as the real release notes (the shape of
> [0.2.1](0.2.1.md)) before the `v0.2.3` tag; items that miss the release
> move to the next one, and anything Pulsar does not finish comes first.

NovaOS 0.2.3 "Nebula" is planned as the release that makes Store apps
feel installed rather than started from a terminal, gives XAML apps text
input, and runs a real vendor display driver unchanged on NovaOS's WDDM
host before the Intel driver meets the T14.

## Must

1. **XAML text input** (size L). A windowless RichEdit (`ITextServices`
   and `ITextHost` in `msftedit.dll`) under XAML's `TextBox`,
   `PasswordBox` and `RichEditBox`, with the caret, selection, clipboard
   and the touch keyboard's input scope. If Pulsar lands `TextBox`, this
   item is the other two and the clipboard. Done when a XAML page's text
   boxes take typing, selection, cut and paste in a CI check.
   First part done: the windowless Rich Edit.  `WinUIEdit.dll`, which
   XAML's text boxes load by name, exports `CreateTextServices`,
   `ShutdownTextServices` and the IIDs XAML checks, and its
   `ITextServices2` object (`userland/textserv/textserv.c`, also behind
   `msftedit.dll`'s and `riched20.dll`'s `CreateTextServices`) keeps the
   text, selection, undo and redo, answers typing, the editing keys, the
   mouse, the clipboard (a password box never copies) and the Rich Edit
   text and selection messages, tells its host `EN_CHANGE`,
   `EN_SELCHANGE` and `EN_MAXTEXT`, moves the host's caret and draws with
   `TxDraw`; the core suite's `textservtest` (64- and 32-bit) is a host
   that checks all of it, the drawing by its pixels.
   Second part done: the Text Object Model and Direct2D drawing.  The
   text services answer `ITextDocument2` (and `EM_GETOLEINTERFACE` an
   `IRichEditOle`) with ranges and a selection (`ITextRange2`,
   `ITextSelection2`; `userland/textserv/tom.c`) that move by
   characters, words, lines, paragraphs and the story, take text in and
   out, find, cut, copy and paste, give points, undo with `tomSuspend`,
   and follow every edit; `TxDrawD2D` draws onto a Direct2D render
   target, opaque or over the host's background.  `textservtest` drives
   them as `TextBoxBase` and `TextBoxView` do.
   Third part done: a typable `TextBox` on a XAML page.  XAML's text box
   controls (`TextBoxBase`, `TextBox`, `TextBoxView`, `TextServicesHost`
   and the framework's `TextBox`) are built from their sources and load
   `WinUIEdit.dll`, which draws their text with DirectWrite glyph runs
   in the host's font and takes their pointer input; the default styles
   keep the text boxes' templates.  `xamlpagetest` clicks a `TextBox`,
   types "Hi!", presses Backspace, counts `TextChanged` and finds the
   text's pixels.
   Fourth part done: `PasswordBox`, `RichEditBox` and the clipboard.  Both
   controls are built from their sources; a `RichEditBox`'s `Document`
   is `WinUIEdit.dll`'s Windows Runtime `ITextDocument` over its Text
   Object Model, and the text boxes' cut, copy and paste ask the control
   first (its `CuttingToClipboard`, `CopyingToClipboard` and `Paste`
   events).  `xamlpagetest` selects all of a `TextBox` with Ctrl+A,
   copies, pastes, cuts and pastes again through the clipboard, types a
   password into a `PasswordBox` (Ctrl+C copies nothing) and text into a
   `RichEditBox`, read back from its `Document` and copied: the item's CI
   check.  Left for later: the context menus (WinUI's text command bar
   flyouts), rich text formats, and the touch keyboard's input scope.
2. **Packaged apps in the shell** (size M). An installed package's apps
   appear in the Start menu with their tile logo and display name from
   the manifest, start from there, and are listed and removed in
   Settings > Apps; a package's app is suspended when minimised and
   resumed when restored (`CoreApplication.Suspending` and `Resuming`).
   Done when the devices or core suite installs a test package, starts it
   from Start, suspends and resumes it, and removes it from Settings.
   First part done: Start lists packaged apps from the package repository
   with the manifest's display name and tile logo (`appx` records the
   logo file, a scale or target-size variant as Windows picks one) and
   starts them packaged; Settings > Apps lists the packages and
   uninstalls one (`kernel/apps/settings_apps.c`); the core suite's
   `889-appxshell.py` checks both.  Second part done: suspend and
   resume.  A `CoreApplication` app's window minimised enters the
   background (`EnteredBackground`) and a second later is suspended
   (`Suspending`, which waits up to five seconds for the deferrals its
   handlers take); restored, it resumes (`Resuming`, then
   `LeavingBackground`); `coreapptest` checks the order and the deferral.
   Third part done: a suspended app is frozen, all its threads stopped
   until its window is restored (from the taskbar, Alt+Tab or another
   program's `ShowWindow`), which `coreapptest` checks from a second
   process ([history](../history/2026-11-17-suspended-apps-frozen.md)).
   Left for later: XAML's own `Application.Suspending` (its process
   lifetime handler is not built yet).
3. **A vendor WDDM display driver, unchanged** (25.3 groundwork, size M
   to L). Red Hat's `viogpudo.sys` from the virtio-win package (BSD
   licensed, Microsoft-signed) installs by hardware ID on QEMU's
   virtio-gpu and drives the display through NovaOS's `dxgkrnl.sys`
   stand-in, instead of NovaOS's own test driver. This is the check
   [the Intel GPU design](../design/intel-gpu.md)'s step 2 makes on the
   T14, done first on hardware CI has. Done when a devices-suite boot
   reaches the desktop on `viogpudo.sys` and Settings changes its mode.
   Done: the devices suite's `viogpudo` boot installs virtio-win
   0.1.302's package by hardware ID on QEMU's virtio-vga, the desktop
   moves to it, and `disptest` changes its mode through the same call
   Settings makes; disabling it gives the screen back, and it starts at
   boot. Running it found two `dxgk.h` layouts NovaOS's own test driver
   could not catch (the source mode's `Stride` is a DWORD; a target mode
   is 96 bytes) and confirmed the display-only registration IOCTL.
4. **Signed updates** (23.5, size S to M, needs Dean if Pulsar did not do
   it). The release public key in `kernel/fs/update_key.h`, channel files
   signed by the release workflow, and the update refusing an unsigned or
   wrongly signed channel. Done when CI shows a signed test update
   accepted and an unsigned one refused, and the 0.2.3 release's channel
   file is signed.

## Nice

5. **Wi-Fi enterprise networks** (28.1, size M to L): WPA2- and
   WPA3-Enterprise with EAP-PEAP (MSCHAPv2) and EAP-TLS, the last Wi-Fi
   gap Starlight's notes list, on the devices suite's modelled access
   point.  Done: WPA2-Enterprise with PEAP and MS-CHAPv2 (`netsh wlan
   connect name=SSID user=NAME key=PASSWORD`,
   [history](../history/2026-11-16-wifi-enterprise.md)), and EAP-TLS with
   a certificate from `certutil -importpfx` (`netsh wlan connect
   name=SSID user=NAME`, [history](../history/2026-11-16-wifi-eap-tls.md)),
   kept across restarts ([history](../history/2026-11-17-wifi-certificates-kept.md)),
   and Enterprise profiles in `wlanapi.dll` with `certutil -delstore`
   ([history](../history/2026-11-17-wifi-enterprise-profiles.md)),
   and WPA3-Enterprise ([history](../history/2026-11-18-wpa3-enterprise.md)).
   All done in QEMU; the T14's card is Dean's check.
6. **Deeper idle** (28.4, size M): PoFx runtime idle for Windows drivers
   (`PoFxRegisterDevice` components) and `_LPI` low-power idle states,
   checked in the `laptop` boot, ready for the T14's idle-drain
   measurement.
7. **A steady performance budget** (size S): make the `smpstress`
   file-access scaling sample, the remaining flake in the performance
   budget job, measure something stable rather than taking best of three.
8. **Pulsar's leftovers**: any of 0.2.2's nice items not done there
   (none left: Settings > Bluetooth landed in 0.2.2 with #608).

## Not in this release

Checks on the T14 itself (the Intel driver's step 2 and 3D, Wi-Fi,
Bluetooth, camera, battery, 23.2, 24.5, 25.4, 25.5) and store sign-ins
(24.1, 24.2, 24.6) need Dean's hardware or accounts; they tick whenever
they are done and do not hold the release. App compatibility rounds stay
paused (OS work only); Secure Boot needs a signing arrangement outside
the repository and is not planned yet.
