> **Planned, not released.** This is the scope NovaOS 0.2.3 "Nebula" is
> working towards, agreed on 2026-10-26, after 0.2.2 "Pulsar" was planned
> ([0.2.2.md](0.2.2.md)). The release-prep pull
> request rewrites this file as the real release notes (the shape of
> [0.2.1](0.2.1.md)) before the `v0.2.3` tag; items that miss the release
> move to the next one, and anything Pulsar does not finish comes first.

NovaOS 0.2.3 "Nebula" is planned as the release that makes Store apps
feel installed rather than started from a terminal, gives XAML apps text
input, and runs a real vendor display driver unchanged on NovaOS's WDDM
host before the Intel driver meets the T14.

## Must

1. **XAML text input** (size L). A windowless RichEdit (`ITextServices`
   and `ITextHost` in `msftedit.dll`) under XAML's `TextBox`,
   `PasswordBox` and `RichEditBox`, with the caret, selection, clipboard
   and the touch keyboard's input scope. If Pulsar lands `TextBox`, this
   item is the other two and the clipboard. Done when a XAML page's text
   boxes take typing, selection, cut and paste in a CI check.
2. **Packaged apps in the shell** (size M). An installed package's apps
   appear in the Start menu with their tile logo and display name from
   the manifest, start from there, and are listed and removed in
   Settings > Apps; a package's app is suspended when minimised and
   resumed when restored (`CoreApplication.Suspending` and `Resuming`).
   Done when the devices or core suite installs a test package, starts it
   from Start, suspends and resumes it, and removes it from Settings.
3. **A vendor WDDM display driver, unchanged** (25.3 groundwork, size M
   to L). Red Hat's `viogpudo.sys` from the virtio-win package (BSD
   licensed, Microsoft-signed) installs by hardware ID on QEMU's
   virtio-gpu and drives the display through NovaOS's `dxgkrnl.sys`
   stand-in, instead of NovaOS's own test driver. This is the check
   [the Intel GPU design](../design/intel-gpu.md)'s step 2 makes on the
   T14, done first on hardware CI has. Done when a devices-suite boot
   reaches the desktop on `viogpudo.sys` and Settings changes its mode.
4. **Signed updates** (23.5, size S to M, needs Dean if Pulsar did not do
   it). The release public key in `kernel/fs/update_key.h`, channel files
   signed by the release workflow, and the update refusing an unsigned or
   wrongly signed channel. Done when CI shows a signed test update
   accepted and an unsigned one refused, and the 0.2.3 release's channel
   file is signed.

## Nice

5. **Wi-Fi enterprise networks** (28.1, size M to L): WPA2- and
   WPA3-Enterprise with EAP-PEAP (MSCHAPv2) and EAP-TLS, the last Wi-Fi
   gap Starlight's notes list, on the devices suite's modelled access
   point.
6. **Deeper idle** (28.4, size M): PoFx runtime idle for Windows drivers
   (`PoFxRegisterDevice` components) and `_LPI` low-power idle states,
   checked in the `laptop` boot, ready for the T14's idle-drain
   measurement.
7. **A steady performance budget** (size S): make the `smpstress`
   file-access scaling sample, the remaining flake in the performance
   budget job, measure something stable rather than taking best of three.
8. **Pulsar's leftovers**: any of 0.2.2's nice items not done there (the
   Venus present hang, Settings > Bluetooth).

## Not in this release

Checks on the T14 itself (the Intel driver's step 2 and 3D, Wi-Fi,
Bluetooth, camera, battery, 23.2, 24.5, 25.4, 25.5) and store sign-ins
(24.1, 24.2, 24.6) need Dean's hardware or accounts; they tick whenever
they are done and do not hold the release. App compatibility rounds stay
paused (OS work only); Secure Boot needs a signing arrangement outside
the repository and is not planned yet.
