NovaOS 0.2.2 "Pulsar" is the fourth release of NovaOS, the from-scratch
x86-64 operating system that runs native Windows programs: their own
machine code runs directly on the CPU, and NovaOS supplies the NT system
calls, the Win32 API, the loader, the desktop and the drivers they expect.
Starlight (0.2.1) built the XAML framework, WinUI 2 and Windows app
packages. Pulsar makes the system XAML a real Windows component that apps
can activate, gets Windows Calculator's Store package most of the way to
opening, shares GPU memory between programs, and adds Bluetooth to
Settings.

## What is new since 0.2.1

**A system `Windows.UI.Xaml.dll`.** The XAML framework is now a DLL that
Windows apps find the way they do on Windows: `RoGetActivationFactory`
returns `Windows.UI.Xaml.Application` and the other 500 classes from the
registry's `ActivatableClassId` keys, with no registration by the program
itself (`xamldlltest` runs a page that way).

**Windows Calculator, most of the way.** The Store's Calculator package
(installed unchanged since 0.2.1) now starts: its `App` is made, its window
opens, `OnLaunched` runs, and its main page loads through a
`NavigationView` and a `Pivot`. Getting there took the Windows Runtime
classes it asks for, built from open sources where there are any:

- `Windows.System.MemoryManager`, `ThreadPool` and `ThreadPoolTimer`;
- a new `Windows.Globalization.dll` (languages, regions, calendars, number,
  currency and date formatters);
- XAML classes the page uses: `Frame`, `Page`, `Image` and its imaging,
  `Popup`, `MenuFlyout`, `ItemsControl`, `ListView`,
  `LinearGradientBrush`, WinUI's `Pivot`, navigation transitions and
  automation peers;
- compiled XAML read from a package's `resources.pri`, a UWP window's
  events and view, and framework packages' resource maps;
- the Windows Foundation diagnostics classes and `UserActivityRequestManager`.

Calculator does not draw its page or compute yet; see "Not finished" below.

**GPU memory shared between programs.** `D3DKMTShareObjects` and opening an
allocation or fence from an NT handle in another process, and the same
calls from 32-bit programs, as VKD3D-Proton uses them (`kmttest wddm`).
This is step 3, part 6, of the Intel GPU design; Intel's driver itself has
not run yet.

**Bluetooth in Settings.** A **Bluetooth & devices** page searches for
devices, pairs and removes them, and a paired mouse or headset that
reconnects by itself is accepted, so it works after the device is switched
off and on. Checked against modelled devices in QEMU.

**Fixes.**

- A .NET program's unhandled exception now prints the exception and its
  stack trace instead of only "Stack overflow": every thread's stack has a
  guard page, as on Windows.
- ShareX starts again: `ApplicationData.Current` is refused to programs with
  no package identity, as Windows does.
- Opening and closing files no longer queue for the page allocator and two
  process-wide locks, so file access scales with CPUs
  (`smpstress`'s file figure is steady).
- The old `d3dtest present` hang on Direct3D with Venus is retired: its
  cause was fixed in 0.2.1 and no graphics job has hung since.

[docs/compatibility.md]({blob}/docs/compatibility.md) lists every program
checked and how well it runs.

## Starting it

Check the download first: `sha256sum -c nova.iso.sha256` on Linux,
`shasum -a 256 -c nova.iso.sha256` on a Mac.

- **In QEMU** (Linux, macOS, Windows through WSL2): boot `nova.iso` on a
  q35 machine with UEFI firmware (OVMF) and 2 GB of memory; the
  [user guide]({blob}/docs/user-guide.md#trying-it-in-a-virtual-machine)
  has the command lines.
- **In Hyper-V**: a Generation 2 virtual machine with Secure Boot off
  ([docs/hyperv.md]({blob}/docs/hyperv.md)).
- **On a PC** with UEFI and Secure Boot off: write `nova.iso` to a USB
  stick (`dd`, Rufus in DD mode or balenaEtcher) and start from it.
- Started from the ISO, NovaOS runs live and offers **Install NovaOS**.
  The first start of the installed system asks for your name, time zone,
  keyboard layout and display resolution and creates the first account.

## Updates

An installed NovaOS 0.2 or newer updates itself to this release from the
App Store's **Updates** page or with `update` in the Terminal
([docs/updates.md]({blob}/docs/updates.md)); the old kernel comes back if
the new one does not reach the desktop.

## Not finished

- **Windows Calculator does not compute yet.** It starts and loads its
  page, its lists (`ListView`) with their items panel (`ItemsStackPanel`)
  its gradient brushes and its link buttons (`HyperlinkButton`), but next
  stops on the core's text element collection, and the check that Calculator computes `2 + 2`
  has not passed.
  Roadmap step 32.6 and Phase 32 stay open until it does; this work
  continues in 0.2.3.
- **XAML text input** is partly in: see the 0.2.3 notes.
- **Update signing key** (23.5): the code to sign and check update channels
  is in, but the release key pair has not been made, so update channel
  files are still not signed.
- **Waiting on hardware and accounts.** Nothing has been checked on the
  reference PC (a Lenovo ThinkPad T14 Gen 4) since 0.2.1: Wi-Fi, Bluetooth,
  camera, battery, the Intel GPU (steps 23.2, 25.3 to 25.5, 28.1 to 28.4),
  a Hyper-V Generation 2 boot (23.4), Steam, GOG and Epic sign-ins (24.1,
  24.2, 24.6) and Roblox on real hardware (24.5) still need a person with
  that hardware or those accounts. NovaOS is developed and tested in QEMU.
- 3D runs on the CPU (llvmpipe, lavapipe) except in QEMU's virtio-gpu with
  Venus; there is no driver for a real GPU yet.
- Games whose anti-cheat makes its own system calls, such as Roblox's
  Hyperion, stop at start
  ([docs/compatibility.md]({blob}/docs/compatibility.md#roblox-and-anti-cheat)).
