NovaOS 0.2.1 "Starlight" is the third release of NovaOS, the from-scratch
x86-64 operating system that runs native Windows programs: their own
machine code runs directly on the CPU, and NovaOS supplies the NT system
calls, the Win32 API, the loader, the desktop and the drivers they expect.
Kepler (0.2) made NovaOS something to live in; Starlight brings the
Windows app platform under it: the XAML framework that UWP and WinUI apps
are written for, built from Microsoft's own MIT source, with WinUI 2's
controls and Windows app packages. An installed drive C: is now the disk
itself, Settings was rebuilt, and NovaOS has a firewall.

This ISO passed every CI suite before it was published: the core,
network and device self-tests (including starting from this ISO) and the
OpenGL and Direct3D tests.

## What is new since 0.2

**Windows.UI.Xaml and WinUI 2 (Phase 32).** The XAML framework, built
from Microsoft's MIT `microsoft-ui-xaml` sources, now starts the way it
does on Windows and answers under its `Windows.UI.Xaml` names, the system
XAML that UWP and WinUI 2 apps are compiled against.

- **The XAML core and framework build** (32.3): the core services,
  resource dictionaries with merged and theme dictionaries, the object
  writer, the control layer on `CoreMessaging.dll`'s `DispatcherQueue`,
  the value boxer (`wintypes.dll`), the rendering seam, and
  `Application.Start` on the desktop. `XamlReader.Load` loads a page of a
  `Grid`, a `TextBlock` and a `Button` end to end.
- **A XAML page draws and takes input** (32.4): a WinUI 3 page in a
  `Window` is laid out, drawn, clicked and typed into, all built from
  Microsoft's sources: the Windows App SDK's content islands under the
  `Window`, the framework's control styles and theme resources,
  DirectWrite's Windows 10 font model (`IDWriteFactory4` to `7`), the
  render walk, text rendering and composition surfaces on NovaOS's
  DirectComposition, and pointer and keyboard input with NovaOS's own
  gesture recognizer.
- **WinUI 2** (32.5): `Microsoft.UI.Xaml.dll` 2.x built from Microsoft's
  `winui2` sources with no Windows SDK tools (its IDL written to a
  `.winmd`, C++/WinRT's generator vendored); data binding, control
  templates, animation and `DispatcherTimer`; a UWP app's start-up runs
  through to `Window.Current`; `XamlControlsResources` loads whole, and
  WinUI 2's controls (`InfoBadge`, `ProgressBar`, `ProgressRing`,
  `SwipeControl`, `BackdropMaterial`, `ItemsRepeater`, `NavigationView`,
  `RadioButtons`) take their default styles and lay out.
- **App packages** (32.6): `appx` installs, lists, removes and starts
  `.msix` and `.appx` packages, checking every block against the
  package's block map; package identity, packaged Windows Runtime
  classes, `ApplicationActivationManager` and `resources.pri` through
  Microsoft's MRT Core. Signed packages are verified as Windows verifies
  them, framework packages and bundles install, and
  `tools/appx/storefetch.py` downloads a free Store app's packages from
  the Store's own delivery service: Calculator's Store bundle and its
  five frameworks install unchanged, each package of the bundle verified
  by its own signature.
- Along the way: `Windows.UI.Composition`'s later interfaces, property
  sets and animations; `Windows.Foundation.Metadata.ApiInformation`
  (Godot 4.7 asks for it at start); `Windows.Foundation.Uri`.

**Drive C: is the disk.** Installed on a disk, NovaOS used to keep all of
drive C: in memory and write it back behind the scenes. Now an installed
system's C: is its NTFS volume, used in place as on Windows; the RAM disk
is only for the live and installer session. Setup formats drive C: as
NTFS only. Drives on disk keep attributes, times and permissions; Disk
Management and `GetVolumeInformation` report C:'s real volume; NTFS's
writer grows the MFT and makes room in a file's record when a rename
needs it (GIMP's and SuperTux's installers rely on it).

**Settings, rebuilt.** One page framework under every page: each page
scrolls, a narrow window shows a slim sidebar of icons, **Find a
setting** (Ctrl+F) searches every page, `start ms-settings:NAME` and
`settings NAME` open a page, and empty states replace blank pages.

**Network security.** A filtering engine shaped like the Windows Filtering
Platform and the Windows Firewall on top of it: Domain, Private and
Public profiles and rules, `fwpuclnt.dll` and `hnetcfg.dll`
(`INetFwPolicy2`), `netsh advfirewall`, and a Settings > Firewall page. A
new network is Public; whether it may be Private is asked from the
network icon by the clock, never by stealing the focus.

**Laptop hardware, continued.** Wi-Fi joins WPA3-Personal networks (SAE
with management frame protection), and Settings > Wi-Fi and
`wlanapi.dll` join networks too; a paired Bluetooth headset plays (A2DP,
with NovaOS's own SBC encoder) and records (hands-free). Still checked
against modelled devices in QEMU only.

**GPU groundwork.** Command submission, GPU fences, preemption and
timeout recovery for a render driver, the fourth and fifth parts of step 3
of the Intel GPU design; Intel's driver itself has not run yet.

**Hyper-V on a real host.** The first boots on a real Hyper-V host brought
fixes to the synthetic video (packed messages, the screen kept updating
during boot) and to the storage driver, which now sleeps for its answers
instead of polling under the kernel lock.

**Fixes.** The Visual C++ Redistributable's installer window shows again;
idle CPUs return to `PASSIVE_LEVEL` (devices that stopped answering after
boot); Direct3D on Venus no longer hangs on a present fence; a re-enabled
KMDF driver starts every time; `appx remove` reports a folder it cannot
delete.

**CI.** About ten checks per pull request instead of 68, the devices
suite in three shards, apt and ccache caches that keep test jobs from
stalling.

## Starting it

Check the download first: `sha256sum -c nova.iso.sha256` on Linux,
`shasum -a 256 -c nova.iso.sha256` on a Mac.

- **In QEMU** (Linux, macOS, Windows through WSL2): boot `nova.iso` on a
  q35 machine with UEFI firmware (OVMF) and 2 GB of memory; the
  [user guide]({blob}/docs/user-guide.md#trying-it-in-a-virtual-machine)
  has the command lines.
- **In Hyper-V**: a Generation 2 virtual machine with Secure Boot off
  ([docs/hyperv.md]({blob}/docs/hyperv.md)).
- **On a PC** with UEFI and Secure Boot off: write `nova.iso` to a USB
  stick (`dd`, Rufus in DD mode or balenaEtcher) and start from it.
- Started from the ISO, NovaOS runs live and offers **Install NovaOS**,
  on its own disk or beside Windows. The first start of the installed
  system asks for your name, time zone, keyboard layout and display
  resolution and creates the first account.

The [user guide]({blob}/docs/user-guide.md) covers the desktop, the App
Store, files, network and sound; [docs/building.md]({blob}/docs/building.md)
builds the same image from source.

## Updates

An installed NovaOS 0.2 or a newer build of `main` updates itself to this
release: the App Store's **Updates** page, or `update` in the Terminal,
reads this release's `novaos-update.txt`, installs the new kernel and boot
loader, and goes back to the old ones if the new kernel does not reach the
desktop ([docs/updates.md]({blob}/docs/updates.md)). An installation on
NTFS uses its volume as drive C: from the first start of 0.2.1; one on
FAT32, made by an older NovaOS, keeps the old way (C: in a RAM disk saved
to the volume) until it is reinstalled on NTFS
([docs/design/disk-c.md]({blob}/docs/design/disk-c.md)).

## Known limits

- UWP and WinUI apps are at their start: a WinUI 3 page draws and takes
  clicks and keys, and WinUI 2's controls lay out, but a `TextBox` (which
  needs a windowless RichEdit) is not there yet, and Windows Calculator's
  Store package installs but does not start yet.
- NovaOS is developed and tested in QEMU. The reference PC, a Lenovo
  ThinkPad T14 Gen 4 (Intel), boots the 0.2 ISO, but its Wi-Fi,
  Bluetooth, camera, power management and GPU have not been checked on
  the machine itself; [docs/hardware.md]({blob}/docs/hardware.md) says
  what has been verified. Other PCs are untested.
- 3D runs on the CPU (llvmpipe, lavapipe) except in QEMU's virtio-gpu
  with Venus; there is no driver for a real GPU yet.
- Wi-Fi (no enterprise networks) and Bluetooth are tried against modelled
  devices only; no Secure Boot.
- Games whose anti-cheat makes its own system calls, such as Roblox's
  Hyperion, stop at start
  ([docs/compatibility.md]({blob}/docs/compatibility.md#roblox-and-anti-cheat)).
- Update channel files are not signed yet; they are checked by size,
  SHA-256 and version only.
